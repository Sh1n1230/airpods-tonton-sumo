# 競合・参考事例調査：AirPods頭振りトントン相撲 PoC

調査日：2026-11-02（JST）．web_search で候補を集め，web_fetch で実際に開いたページだけを出典にしている．検索結果の抜粋しか見ていないものは末尾の「未検証」にまとめた．並び順はカテゴリ別で，優劣は付けていない．

## 前提：比較の軸にした PoC の構成

- 同じ場所にいる2人が，それぞれ AirPods を装着する．
- iOS の `CMHeadphoneMotionManager` で頷きを検出し，それを1回の「トン」として扱う．
- 1つの Mac 上の Unity で共有のトントン相撲の土俵を描画する．

各項目の「PoC との違い」は，この構成と比べたときに入力・人数・表示のどこが違うかを書いたもの．良し悪しの評価ではない．

## 1．デジタル紙相撲・トントン相撲（アプリ／Web／玩具）

### 1-1．どすこい！バトル - トントン相撲
- プラットフォーム：iOS（2015-12-19 リリース，開発者 Tomoki Ikeda，無料）
- URL：https://dotapps.jp/products/com-Toughwood-DosukoiBattle （アプリ紹介サイト．App Store の現行ページは開いていない）
- 入力：土俵上のタップボタンを連打する
- 人数：1人（ひとりモード），または1台のスマホで2人（ふたりモード）
- 良い点：操作が連打だけで分かりやすい．力士12種類の解放要素がある．
- 弱い点（推測を含む）：入力は連打回数の勝負になりやすく，2人で1画面を挟んで遊ぶ形になる．紹介ページの最終更新は 2018-12-19 で，現在も配信されているかは確認していない．
- PoC との違い：手を使わず頷きで叩く点と，各自の装着デバイスから1つの共有画面へ入力する点．

### 1-2．トントン紙相撲（webサクッとツールズ）
- プラットフォーム：Web ブラウザ
- URL：https://took.jp/tools/kamizumo
- 入力：画面のどこでもタップ，またはキー（スペース，Enter，A，F，J，L）
- 人数：1人（CPU 戦，難易度1〜20）
- 良い点：単純な連打では勝てない設計になっている．「タイミングの輪」で着地の瞬間に叩くと PERFECT／GREAT／GOOD の判定が出て，コンボが続くと押す力が上がる．決まり手（寄り切り，押し出し，はたき込みなど）が出る．自分で力士を描くと，塗りの量で重さが，形で踏ん張りが決まる．
- 弱い点：対人戦の記載はなく，CPU 戦のみ．
- PoC との違い：PoC は人対人で，入力は頷き．ただし「力士が着地する瞬間に叩くと強い」というタイミングの仕組みは，頷きの間隔やリズムをゲームに組み込む参考になる．

- 弱い点：レビューはまだ投稿されておらず，遊んだ人の評価は確認できない．
- PoC との違い：PoC の入力は「頷き＝叩く」の1種類．頭の別方向の動き（首振りなど）を「払う」に割り当てる案を考えるときの比較対象になる．

### 1-7．さけべ！トントンボイス相撲（メガハウス，玩具）
- プラットフォーム：物理玩具（電動で振動する土俵．2018年7月発売，希望小売価格4,378円税込）

- PoC との違い：「手以外の身体入力でトントン相撲をする」という発想は共通．PoC は声ではなく頭の動きで，各自の AirPods が個別のセンサーになるので，プレイヤーごとの入力の分離は構成上はっきりしている．

### 1-8．ポケモン トントンバトル！（ポケモンセンター，玩具）

- 入力：土俵を指でトントンと叩き合う（アナログ）

- 良い点：カビゴン，パーモット，ハリテヤマ，マクノシタを組み立て式にしている．遊んだ後はパーツをアクリルスタンドとして飾れるので，コレクションとしても楽しめる．
- 弱い点：デジタルの要素はない．
- PoC との違い：キャラクター IP と物理玩具の路線で，PoC とは方向が違う．2025年に大手 IP がトントン相撲を新作として出した事実は，題材の現役度を示す材料になる．

## 2．AirPods（ヘッドホンモーション）で操作するアプリ・ゲーム

### 2-1．RidePods - Race with Head
- プラットフォーム：iOS／iPadOS（iOS 15.6 以降，無料，広告や課金はない）
- URL：https://apps.apple.com/us/app/ridepods-race-with-head/id6752268828 ／報道：https://www.theverge.com/news/787396/ride-pods-race-with-head-apple-airpods-spatial-audio-motion-controls
- 入力：頭を左右に傾けてバイクを操舵する．前後の傾きで加減速する設定もあるが，The Verge は効果を感じられなかったと書いている．
- 人数：1人（Game Center のリーダーボードあり）
- 良い点：The Verge は「頭での操舵は思ったより自然で反応が良い．片耳だけでも小さな動きによく反応する」と評価している．プレイ映像と自撮りを1本の動画に録画する機能もある．
- 弱い点：App Store の評価は 3.3（18件）．レビューでは「左に傾く癖が出るので，姿勢のキャリブレーションがほしい」という指摘が複数ある．The Verge は道路が消えるなどの描画の不具合を指摘し，「完成したゲームというより技術デモ」と書いている．
- PoC との違い：RidePods は1人用で，連続値（傾き量）を操舵に使う．PoC は2人対戦で，離散イベント（頷き1回＝トン1回）を共有の盤面に送る．キャリブレーションの要望が多い点は，PoC でも中立姿勢の設定が必要になることを示している．
- 補足：Tom's Hardware と The Verge は，開発者が「空間オーディオ機能をリバースエンジニアリングした」と述べたと報じている．一方 The Verge は，Apple が公式に開発者へヘッドホンのモーションデータを提供しているとも書いている（Tom's Hardware の記事は抜粋のみで，開いていない）．

### 2-2．Head Games: Hands-Free Arcade
- プラットフォーム：iPhone／iPad／Mac（M1 以降，macOS 15）／Apple Vision（iOS 18 以降）．無料で，Pro 解放は $1.99．
- URL：https://apps.apple.com/us/app/head-games-hands-free-arcade/id6759519152
- 入力：AirPods（Pro，Max，第3世代以降）の頭の傾き．AirPods がなければ iPhone 本体のセンサーでも動く．左右に傾けてメニューを移動し，下に頷いて保持するとゲームが始まる．静止すると自動でキャリブレーションされる．
- 人数：1人
- 良い点：メニューからリプレイまで，画面に触れずに完結する．頷きの保持時間を3段階から選べ，「Try It」で練習できる．2048 系やスネーク，ブロック崩しなど7本のゲームと，首のストレッチや可動域の記録をまとめている．VoiceOver に対応．
- 弱い点：評価件数が少なく，評価の概要は表示されていない．
- PoC との違い：「頷き＝決定」を UI として磨いた単独プレイの例．PoC は頷きを対戦の連打入力として使い，2人の入力を同時に処理する．頷き検出の誤作動対策（保持時間，静止キャリブレーション）は参考になる．

### 2-3．TurtleUp for Mac（OSS）
- プラットフォーム：macOS 14 以降（ノッチ周辺に常駐するアプリ）
- URL：https://github.com/mikkley/neckup （turtleup にリダイレクトされる）
- 入力：AirPods の頭部姿勢（`CMHeadphoneMotionManager` を Mac で直接読む）．休憩中の60秒ミニゲームでは，頷き，振り向き，側屈，顎引き，その組み合わせの5方向の動きを使う．
- 人数：1人
- 良い点：装着すると自動でキャリブレーションし，外すと一時停止する．頭を勢いよく振る動きは安全のため受け付けない．センサーの更新頻度は，ポモドーロの時間外は 0.5Hz，集中中と対局中は 25Hz に切り替えて電力を節約している．デバイスなしで開発できる `--mock` モードがある．データは端末内にだけ保存する．
- 弱い点：ad-hoc 署名で公証されていない．スターは3．
- PoC との違い：姿勢改善が主目的．PoC は娯楽の対戦．「急な頭振りを弾く」という安全面の配慮は，頷き連打を競う PoC で特に関係する．

### 2-4．AirTracker（OSS）
- プラットフォーム：macOS 14 以降（メニューバーアプリ）
- URL：https://github.com/crippler95/airtracker
- 入力：AirPods の頭の向き（約25Hz）．OpenTrack の UDP 形式（ポート4242）と JSON の UDP 形式（ポート4243）で送り出す．
- 人数：1人（フライトシムなどのカメラ操作用）
- 良い点：再センタリング，デッドゾーン，expo カーブ，ヨーのドリフト補正，再接続時の自動再センタリングなど，ヘッドトラッキングの実務的な処理がそろっている．
- 弱い点：README は「AirPods がモーションを報告するのは，Mac のアクティブな音声出力になっている間だけ」「iPhone への自動切り替えは無効にする」と注意している．
- PoC との違い：Mac で直接読む構成．README のこの記述からの推論だが，1台の Mac で2組の AirPods を同時に読むのは難しいと考えられ，各プレイヤーに iPhone を1台ずつ用意して Mac へ送る PoC の構成には理由がある．Mac 側の受信処理（UDP，再センタリング）は参考になる．

### 2-5．Apple 公式：CMHeadphoneMotionManager とサンプル
- プラットフォーム：iOS 14.0 以降，iPadOS 14.0 以降，Mac Catalyst 14.0 以降，macOS 14.0 以降，watchOS 7.0 以降
- URL：https://developer.apple.com/documentation/coremotion/cmheadphonemotionmanager
- 内容：ヘッドホンのモーションを取得するクラス．`Info.plist` に `NSMotionUsageDescription` がないと，更新を開始した時点でアプリがクラッシュする．公式サンプル「Getting motion-activity data from headphones」（iOS 18.0 以降）は `CMHeadphoneActivityManager` で動作の種類の変化を受け取るもので，頷きを検出するサンプルではない（検索の抜粋による．サンプルのページは開いていない）．
- PoC との違い：これはゲームではなく基盤 API．頷き検出のロジックは自前で作る必要がある．

## 3．頭部ジェスチャー・体を使うローカルマルチの参考点

### 3-1．1-2-Switch（任天堂）
- プラットフォーム：Nintendo Switch（Switch 2 でも動作するが，IR カメラを使うミニゲームは初代 Joy-Con が必要）．2017-03-03 発売，5,478円税込．
- URL：https://store-jp.nintendo.com/item/software/D70010000000027
- 入力：Joy-Con の HD 振動，モーションセンサー，IR カメラ
- 人数：1〜2人
- 良い点：コンセプトが「見るのは画面ではなく相手の目」．観客がプレイヤー本人を見て楽しむ構造になっている．
- 弱い点：My Nintendo News は，後継作のレビューの中で初代を「洗練や魅力に欠け，フルプライスだった」と書いている（https://mynintendonews.com/2023/07/15/review-everybody-1-2-switch ）．
- PoC との違い：PoC は共有の盤面を見る前提だが，頷く姿そのものが見ていて面白いので，観客から見た面白さという点で 1-2-Switch の発想と重なる．コントローラーを持たない点が違う．

### 3-2．エブリバディ 1-2-Switch!（任天堂）
- プラットフォーム：Nintendo Switch（2023-06-30 発売）．Joy-Con モードは最大8人，スマホモードは最大100人．
- URL：https://mynintendonews.com/2023/07/15/review-everybody-1-2-switch （レビュー）／https://www.nintendo.com/jp/switch/argta/index.html （公式．検索の抜粋のみで，開いていない）
- 入力：Joy-Con の動き，またはスマホ（QR コードで参加）
- 人数：2チーム戦
- 良い点：収録ミニゲームの「Hip Bump」は，腰の動きで相手を土俵の外へ押し出すゲームで，体の動きで押し出す相撲という点が PoC に直接近い．レビューは，スマホが QR コードで簡単につながり，遅延もほとんど感じなかったと評価している．
- 弱い点：同レビューの評価は 5.5/10．司会の説明が冗長で，現実でやれば済む遊びを置き換えただけに見えるミニゲームがあるとの指摘がある．
- PoC との違い：PoC は頭の頷きで盤面の力士を間接的に動かす．Hip Bump は Joy-Con を持って腰を振る．「デジタルにする意味」を問われやすい点は共通の課題になる．

### 3-3．Just Dance（Ubisoft）＋ Just Dance Controller アプリ
- プラットフォーム：Switch／Switch 2／Xbox Series X|S／PS5 と，iPhone 用のコントローラーアプリ（iOS 15 以降）
- URL：https://apps.apple.com/us/app/just-dance-controller/id1634629424 ／https://www.ubisoft.com/en-us/game/just-dance/2026/news-updates/5NJUNzf4Y05YKoZ7y4SixM/just-dance-2026-edition-is-out
- 入力：右手に持ったスマホのモーションで採点する．2026 Edition からは，スマホのカメラで全身を追跡する Camera Controller モードも追加された．
- 人数：最大6人のローカルマルチ
- 良い点：持っているスマホを専用機器なしでコントローラーにする．PoC の「iPhone を中継に使う」構成の大規模な先行例．
- 弱い点：コントローラーアプリの App Store 評価は 2.0（約2,000件）．レビューには，iPhone が Xbox につながらないという接続トラブルや，旧作・Kinect が非対応になったことへの不満がある．
- PoC との違い：PoC は手ではなく頭の動きで，ペアリングの対象がゲーム機ではなく Mac．Just Dance のレビューは，スマホとホスト機の接続の安定性が体験を大きく左右することを示している．

### 3-4．Heads Up!（Warner Bros.）
- プラットフォーム：iOS（$1.99，課金あり）／Android
- URL：https://apps.apple.com/us/app/heads-up/id623592465
- 入力：額に当てたスマホを下に傾けると正解，上に傾けるとパス．実際には頭を上下に振る動作になる．
- 人数：グループ（何人でも）
- 良い点：「頭を下げる＝はい」という直感的な割り当てで，パーティーゲームの定番になった．App Store の評価は 4.8（30万件）．プレイ中の様子を動画で残せる．
- 弱い点：レビューでは，デッキが消える，購入したデッキが復元できないなど，運営面の不満が目立つ．
- PoC との違い：Heads Up! はスマホ本体のセンサーで頭の上下動を読み，1人ずつ交代で答える．PoC は AirPods で読み，2人が同時に入力する．頷きを入力として使うことが一般の利用者にも受け入れられている根拠の1つになる．

## 4．CMHeadphoneMotionManager を使った個人・開発者プロジェクト

### 4-1．Kishimen（takanakahiko）
- プラットフォーム：iOS → UDP → 任意の受信先（README に Unity との連携例の GIF がある）
- URL：https://github.com/takanakahiko/Kishimen
- 入力：AirPods Pro のモーション（`CMHeadphoneMotionManager`）を，UDP で任意のアドレスとポートへ送る
- 人数：1台分の送信（複数台の利用は README に記載なし）
- 良い点：「iPhone で読み取り，ネットワークで Unity に送る」という PoC と同じデータの流れを，2020年の時点で実装している．MIT ライセンス，スター10．
- 弱い点：作者自身が学習用と位置付けている．最後の push は 2020-12（検索結果のメタデータによる）．
- PoC との違い：Kishimen はセンサー値を中継するだけ．PoC は2台分を同時に受け，頷きをイベントとして判定して，対戦ゲームに組み込む．

### 4-2．HeadphoneMotion Unity Plugin（anastasiadevana）
- プラットフォーム：Unity から iOS 向けにビルドするネイティブプラグイン（検証環境は Unity 2019.4.1f1，Xcode 12 以降，iOS 14 以降）
- URL：https://github.com/anastasiadevana/HeadphoneMotion
- 入力：AirPods の回転（3DoF の Quaternion）をコールバックで受け取る
- 人数：端末1台
- 良い点：スター308，フォーク22で，この分野の Unity 向け実装として広く参照されている．README に「回転の基準がずれるのは片方の AirPod の装着位置が原因．データには片耳だけが使われる」という注意と，キャリブレーション用のボタンがある．
- 弱い点：iOS 端末上で Unity を動かす前提なので，Mac で描画する PoC の構成にはそのまま当てはまらない．
- PoC との違い：PoC の描画側は Mac 上の Unity．このプラグインは「iPhone 側も Unity で作る」場合の選択肢になる．

### 4-3．AirPodsの首振り・頷きジェスチャーを検知するiOSアプリ（Zenn，ひとのみち）
- プラットフォーム：iOS（Swift，記事は 2026-01-26 公開）
- URL：https://zenn.dev/hitonomichi/articles/c7c4a03bc76723 （サンプルコード：https://github.com/hitonomichi/iOS-Samples/blob/main/SampleDeviceMotion/ ．こちらは開いていない）
- 入力：`attitude.pitch`（頷き）と `attitude.yaw`（首振り）の，前のフレームとの差分
- 人数：1人
- 良い点：頷き検出の具体的なパラメータを示している．閾値は 0.04 rad／フレーム（約2.3度）を推奨値とし，0.08 では大きく動かす必要があったと書いている．誤検知を防ぐクールダウンは 0.5 秒．AirPods（第4世代）と AirPods Pro（第3世代）で検証している．記事は，設定の「頭のジェスチャー」を ON にする手順も挙げている．
- 弱い点：この方式はフレーム間の差分で判定するので，更新レートが変わると感度も変わると考えられる（推論）．
- PoC との違い：PoC は検出結果を連打入力として使う．クールダウン 0.5 秒は，連打の上限（毎秒2回程度）とそのまま関係するので，ゲームの調整と一緒に決める必要がある．

### 補足：開発上の制約に触れた資料（表には含めない）
- Anand Chowdhary のメモ（https://anandchowdhary.com/notes/2025/airpods-based-head-motion-racing/ ）：取得できるのは約25Hz の `CMDeviceMotion`．制約として，3DoF のみであること，更新レートの低さ，ヨーのドリフト，デバイスの自動切り替え，装着が緩んだときの挙動を挙げている．毎回の中立姿勢キャリブレーションと，読み取りから描画までの遅延の管理が重要だとしている．
- Kalpana One（https://apps.apple.com/us/app/kalpana-one/id6741139397 ）：AirPods または Apple Watch で「静止を保つ」ことを操作にした瞑想ゲーム（iOS 18 以降）．入力の向きが PoC とは逆（動かないこと）なので，表から外した．

## 調べた範囲から言えること（解釈を含む．判断は利用者に委ねる）

- 今回開いた範囲では，「AirPods の頷きで2人が同時に対戦する」ゲームや，「AirPods で操作するトントン相撲」は見つからなかった．見つからなかったというだけで，存在しないとは言えない．
- 構成が最も近いのは 1-4 Tonton Sumo（共有画面＋各自のスマホ）と 4-1 Kishimen（iPhone から UDP で Unity へ）．手以外の身体入力でトントン相撲をする発想の先行例は 1-7 トントンボイス相撲（声）で，体の動きで押し出す相撲は 3-2 Hip Bump（腰）．
- 複数の資料に共通する技術上の注意点：更新は約25Hz（2-3，2-4，補足のメモ），中立姿勢のキャリブレーションの要否（2-1 のレビュー，4-2），ヨーのドリフト（2-4，補足のメモ），AirPods がアクティブな音声出力の間だけ値を出すこと（2-4，macOS の文脈），頷き検出の閾値とクールダウン（4-3）．
- 体験面の注意点：スマホとホスト機の接続トラブルは評価を大きく下げている（3-3）．「現実のアナログ遊びより面白いか」はデジタル化したパーティーゲームでよく指摘される（3-2）．
